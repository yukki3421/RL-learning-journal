## 阶段一：补齐 RL 最小基础

预计投入：1–2 天；若首次接触 RL，可适当延长。

### 学习内容

1. 状态与观测、动作、奖励、轨迹、episode、折扣回报。
2. 策略、状态价值函数 V、动作价值函数 Q、优势函数 A。
3. 策略梯度：为什么提高高优势动作的概率。
4. Actor-Critic 与 GAE：如何估计优势。
5. PPO：新旧策略概率比、裁剪目标、价值损失、熵奖励。
6. On-policy 数据的使用方式，以及采样与参数更新之间的关系。

### 实践

- [ ] 在 CartPole 等小环境中跑通一个现成 PPO 实现。
- [ ] 找到观测、动作、奖励、终止标记和轨迹缓存。
- [ ] 找到回报与优势计算、策略损失、价值损失和参数更新。
- [ ] 查看训练曲线，保存模型并单独运行评估。

不要求先从零实现完整 PPO，但需要能沿着代码解释一次更新。

### 完成标准

- 能解释 rollout 和 update 分别做什么。
- 能解释 reward、return、value 和 advantage 的区别。
- 能解释 PPO 为什么保存旧策略的动作对数概率。
- 能解释为什么训练损失下降不等于任务成功率提高。

## 阶段二：将 RL 概念对应到 VLA

预计投入：半天–1 天。

| RL 概念 | VLA 场景中的对应内容 |
| --- | --- |
| Observation | 相机图像、语言指令、本体状态等模型输入 |
| Policy | 根据输入生成动作或动作序列的 VLA |
| Action | 关节控制、末端位姿增量、夹爪指令等 |
| Environment | 机器人仿真环境；第一轮以仿真为主 |
| Reward | 任务成功信号或环境定义的其他奖励 |
| Episode | 从环境重置到任务终止或达到时间上限的一段交互 |
| Rollout | 用当前策略采集的交互数据 |
| Update | 根据采集数据更新策略及算法需要的其他网络 |

### 需要特别检查的具身细节

- **动作归一化**：模型输出如何转换成环境接受的动作，是否使用正确的统计量。
- **控制频率**：一次动作对应多少仿真步，策略多久重新观察一次。
- **Action chunk**：生成多少步、实际执行多少步，奖励、折扣和对数概率如何对齐。
- **终止与超时**：区分任务终止和时间截断，确认价值估计如何处理。
- **稀疏奖励**：初始策略能否采到成功轨迹，全失败批次是否有可用的学习信号。
- **部分可观测性**：单帧观测是否足够，策略是否需要历史信息。

### 完成标准

- [ ] 画出“观测 → VLA → 动作 → 仿真 → 奖励 → 更新”的数据流。
- [ ] 明确所选实现中的观测、动作和奖励格式。
- [ ] 明确动作或动作序列的概率如何参与 RL 损失。
- [ ] 明确哪些参数会更新，哪些参数被冻结。

## 阶段三：跑通一个 VLA＋RL 项目

预计投入：2–4 天起；环境配置和算力不足可能显著延长时间。

### 项目选择

| 项目 | 适合的学习目标 | 本路线中的安排 |
| --- | --- | --- |
| [RL4VLA](https://github.com/gen-robot/RL4VLA) | 理解 RL 对 VLA 行为和泛化的影响 | 默认优先考虑，先做单任务 PPO |
| [RLinf](https://github.com/RLinf/RLinf) | 搭建可持续扩展的 VLA＋RL 实验平台 | 若更看重框架扩展，作为第一项目的替代选择 |
| [DSRL](https://github.com/nakamotoo/dsrl_pi0) | 理解冻结基础策略、通过潜空间 RL 引导动作生成 | 后续分支；选这条路线时再补 SAC |

RL4VLA 和 RLinf 第一轮二选一。DSRL 的学习重点与直接更新 VLA 不同，不必同时开展。

### 步骤 1：环境与基线评估

- [ ] 记录仓库 commit、依赖版本、模型检查点和配置。
- [ ] 跑通仿真环境及视频保存。
- [ ] 使用作者提供的检查点评估单个任务。
- [ ] 记录成功次数、评估总次数和若干成功/失败视频。
- [ ] 确认初始策略能产生可用的奖励信号；若完全失败，先检查环境、动作接口和检查点适配。

### 步骤 2：最小训练闭环

- [ ] 找到 rollout 采集入口。
- [ ] 找到奖励、回报和优势的计算位置。
- [ ] 找到策略损失，以及实现所需的价值网络或其他组件。
- [ ] 确认实际训练的参数与配置一致。
- [ ] 完成若干轮采样和更新，检查数值是否有限、奖励与终止统计是否合理。
- [ ] 保存检查点，并在独立评估流程中重新加载。

### 步骤 3：阅读训练日志

优先关注：

- 任务成功率和 episode return。
- Episode 长度及终止原因。
- 优势统计、策略损失、价值损失。
- 实现提供的 KL、clip fraction、熵等更新指标。
- 环境采样耗时、模型更新耗时和显存占用。

这些指标用于定位问题，需要结合任务表现解释；不要求每项都单调改善。

### 完成标准

能够完整说明一次训练迭代的数据来源、奖励来源、优势计算和参数更新，并能加载保存的模型完成评估。

## 阶段四：训练前后比较与小实验

预计投入：1–2 天；充分验证可能需要更长时间。

### 基础比较

- [ ] 预先固定一批独立于训练的评估种子或初始状态。
- [ ] 训练前后使用相同评估集合、任务设置、时间上限和推理配置。
- [ ] 同时报告成功次数与评估总次数，不只记录百分比。
- [ ] 对比失败视频，观察抓取、移动、放置或终止判断的变化。
- [ ] 将训练环境步数和耗时一起记录。

### 只增加一个实验变量

根据学习目标选择其一：

- **训练消融**：只改变一个因素，例如学习率或每批数据的更新轮数，保持采样预算和评估条件一致。
- **泛化测试**：在环境支持的范围内，只改变物体初始位置、背景或其他一个因素，比较训练前后的表现。

泛化测试与训练消融回答不同的问题，记录时应明确区分。

### 结果解释

- 跑通训练闭环，说明工程流程可用。
- 在固定评估集合上提高成功率，说明这次实验在该条件下观察到改善。
- 单次训练、少量评估不足以证明稳定提升；需要时增加评估次数和独立训练种子。
- 泛化能力需要在明确改变的测试条件下验证，不能从训练任务成功率直接推断。

## 后续扩展顺序

1. **PPO → GRPO**：理解组内相对奖励构造优势的方式，以及全成功或全失败组的问题。
2. **PPO → SAC → DSRL**：补齐 Q 学习、经验回放、离策略训练和熵正则，再研究潜空间策略。
3. **单任务 → 多任务与泛化**：研究任务分布、评估划分和能力遗忘。
4. **实验复现 → 框架扩展**：在已有闭环上尝试新的 VLA、环境或训练配置。
