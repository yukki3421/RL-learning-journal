# 06 · 第一次代码实践：认识 Gymnasium 与 CartPole

前置知识：[策略如何学习](05-how-policy-learns.md)。本课先补齐代码练习的任务背景，再开始手写。

目标：能说明我们在控制什么、模型会看到什么、动作会改变什么，以及环境如何给出反馈。

## 1. 先区分三个角色

| 名称 | 它是什么 | 在本项目中负责什么 |
| --- | --- | --- |
| Gymnasium | 一个 Python 库，提供统一的环境接口和多种环境实现 | 创建环境，执行动作，返回观测、奖励和结束标记 |
| CartPole | Gymnasium 中的一个控制任务 | 模拟“小车移动，让杆保持直立” |
| PyTorch | 张量计算与深度学习库 | 实现策略网络、计算损失和梯度、更新参数 |

而你要写的是：**如何根据观测选择动作，以及如何根据交互数据更新策略。**

可以理解成：Gymnasium 提供练习场，CartPole 是具体的练习项目，PyTorch 是实现可训练策略的工具。

本课和下一步先认识练习场，还没有进行模型训练。

## 2. CartPole 到底在做什么？

Cart 是小车，Pole 是杆。杆通过可以转动的连接点装在小车上。

```text
          /  ← 杆可能向一边倾斜
         /
        ●    ← 杆与小车的连接点
     ┌─────┐
     │小车 │
     └─○─○─┘
─────────────── 水平轨道
     ←     →
```

你可以给小车施加向左或向右的力。小车移动会影响杆的运动。目标是通过连续控制，让杆尽量保持直立，同时避免小车离中心太远。

可以想象用手掌托住一根直立的棍子：棍子开始倾斜时，你需要移动手掌，持续调整，而不是只做一次动作。

我们使用的环境名称是 `CartPole-v1`。这个名称用于创建任务，不是训练算法名称。

## 3. 对应你已经学过的 RL 概念

| RL 概念 | CartPole 中的对应内容 |
| --- | --- |
| 环境 | 小车、杆和模拟它们运动的规则 |
| 观测 | 小车位置、速度，杆的角度、角速度 |
| 策略 | 根据这四个数，决定向左推还是向右推 |
| 动作 | 向左施力或向右施力 |
| 奖励 | 默认每执行一步获得 1，包括导致终止的那一步 |
| Episode | 从一次重置开始，到失败终止或达到时间上限 |
| Rollout | 按策略与环境交互并收集数据的过程 |

我们的第一个学习任务仍然是同一条链：

```text
读取观测 → 选择动作 → 环境执行 → 返回新观测和奖励 → 继续
```

这一套接口以后也能帮助你理解具身任务中的图像输入、机器人动作与奖励反馈。

## 4. 策略看到什么？四个观测值

CartPole 默认给策略的输入是一个包含四个数的数组，顺序固定：

```text
observation = [小车位置, 小车速度, 杆的角度, 杆的角速度]
```

| Python 索引 | 含义 | 帮你理解的说法 |
| --- | --- | --- |
| `observation[0]` | 小车位置 | 小车当前离轨道中心多远 |
| `observation[1]` | 小车速度 | 小车当前移动得多快、朝哪个方向 |
| `observation[2]` | 杆相对竖直方向的角度 | 杆现在倾斜了多少，单位是弧度 |
| `observation[3]` | 杆的角速度 | 杆的角度正在以多快的速度变化 |

这里的输入是描述当前物理状态的数值，当前练习直接将它们作为策略输入。后面写策略网络时，网络输入维度就是 4。

角度接近零表示接近直立。只看角度还不够：两根杆虽然此刻角度相同，一根可能正在倒下，另一根可能正在恢复直立，角速度会帮助区分这种情况。

**`observation` 是当前的一组具体数值；`observation_space` 是这些数值的格式说明。**

例如，观测空间中的 `(4,)` 表示一个长度为 4 的一维数组；`float32` 表示数值类型。打印空间时出现的上下界不一定就是任务失败阈值，不能混用。

## 5. 策略能做什么？两个动作

| 动作编号 | 含义 |
| --- | --- |
| `0` | 向左推小车 |
| `1` | 向右推小车 |

动作空间打印为 `Discrete(2)`，表示可以选择编号 0、1 这两个离散动作。

动作不是“把小车直接放到最左边或最右边”，而是在这一个模拟步施加相应方向的力。下一步可以重新观察、重新决定。

后面策略网络可以为这两个动作生成概率，例如向左 0.7、向右 0.3，再据此抽取动作。

这两个数描述的是**选择动作的概率**，不能直接解释为任务成功概率。

## 6. 什么算表现好？先理解奖励

本练习采用 CartPole 的默认奖励规则：每一步奖励都是 1，包括触发失败终止的那一步。

如果两次运行分别持续了 12 步和 40 步，它们的原始奖励和为：

$$
\sum_{t=0}^{11}r_t=12,\qquad
\sum_{t=0}^{39}r_t=40
$$

在 $\gamma=1$ 时，这也分别是从起点开始的回报；使用折扣后，40 步轨迹的起点回报为：

$$
G_0=1+\gamma+\gamma^2+\cdots+\gamma^{39}
$$

因此，策略需要学会延长可持续控制的时间。单看某一步拿到 1，不能说明该动作长期效果好；还要看后续能继续获得多少奖励。

之前胡萝卜例子采用“成功时才奖励 1”的规则；CartPole 采用每步奖励 1。**奖励由具体任务定义，RL 没有规定所有任务必须使用同一种奖励。**

## 7. Episode 什么时候结束？

对于默认的 `CartPole-v1`：

| 情况 | 对应结束标记 |
| --- | --- |
| 杆的倾斜角度超过约 12 度 | `terminated=True` |
| 小车位置超出中心两侧约 2.4 的范围 | `terminated=True` |
| 达到环境包装器设置的 500 步上限 | `truncated=True` |

时间上限并不表示杆必然倒下，而是环境结束本次运行。这正是第 2 课区分“真正终止”和“外部时间截断”的一个具体例子。

控制交互循环时，任意一个标记为真都需要停下；开始下一次 episode 前调用 `reset()`。但在计算带价值自举的学习目标时，两个标记的意义不同，需要按任务目标处理，不能只合成一个结束标记就丢弃原始信息。

到达 500 步表示撑到了当前运行上限，不能据此声称在任何初始状态下都能稳定控制。

## 8. Gymnasium 把交互写成哪些代码？

先导入库：

```python
import gymnasium as gym
```

`gym` 是我们给 `gymnasium` 起的代码别名。

创建环境：

```python
env = gym.make("CartPole-v1")
```

它创建了一个可交互的环境对象，还没有创建策略网络。

开始一次任务：

```python
observation, info = env.reset(seed=7)
```

- `observation`：初始观测，对应本次 episode 的起点。
- `info`：额外信息字典，CartPole 初始化时通常为空。
- `seed=7`：设置环境随机种子，帮助复现初始化；这里的 7 不是状态编号。

执行一步动作的接口是：

```python
next_observation, reward, terminated, truncated, info = env.step(action)
```

按顺序返回：新的观测、本步奖励、真正终止标记、时间截断等标记、额外信息。

对应笔记中的时间约定：

$$
o_t\xrightarrow{a_t,\;r_t}o_{t+1}
$$

这里 `reward` 是刚执行动作后收到的 $r_t$，`next_observation` 是新观测 $o_{t+1}$。

最后调用 `env.close()` 释放资源。当前使用无图形窗口模式，便于在远程终端学习。

## 10. 实测：为什么一直向左推，9 步就结束了？

在手写代码中使用 `seed=7` 初始化，每一步都执行 `action=0`。我们复现后得到：

| 已执行步数 | 小车位置 | 杆的角度，已换算为度 | 是否真正终止 |
| --- | --- | --- | --- |
| 0，初始 | 0.01251 | 1.58 | 否 |
| 1 | 0.01330 | 1.55 | 否 |
| 3 | 0.00316 | 2.52 | 否 |
| 6 | -0.04139 | 6.60 | 否 |
| 8 | -0.09070 | 11.13 | 否 |
| 9 | -0.12123 | 13.96 | 是 |

这段固定策略持续向左施力，没有根据杆的状态调整动作。杆逐渐倾斜，第 8 步还没超过 12 度，第 9 步已经超过阈值，因此 `terminated=True`，循环退出。此时小车位置仍在允许范围内，也没有达到 500 步时间上限，所以结束原因是杆角度越界，`truncated=False`。

9 不是预先设置的循环次数，而是这组初始状态和动作序列产生的结果。改变种子或动作，持续步数可能不同。

`step_count += 1` 在检查结束之前执行，所以触发失败的第 9 次动作也计入总步数。默认这一步仍然奖励 1，因此总步数为 9，原始奖励和也为 9。

**结束之后不能继续调用 `step()`。** 如果循环后仍保留了之前的单步示例，会在已终止的状态下多执行一次动作，产生警告；打印的“最终观测”也会变成这次无效调用之后的结果。应使用循环最后一次返回的数据，需要开始新 episode 时先 `reset()`。
